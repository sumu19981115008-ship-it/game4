## 1. 世界观设定

### 1.1 背景概述

**时间线**：卡洛斯地区 X/Y 事件（闪焰队危机）结束五年后，即游戏内历法「新纪元 5 年」。

露米欧丝城（Lumiose City）在 X/Y 事件后经历了大规模城市重建计划——「卢米欧丝再开发计划（Plan Lumios Reconquista，简称 Z-A 计划）」。该计划以「让城市与宝可梦共存」为核心理念，将原先严格划分的人类居住区与宝可梦栖息地融合重组，使城市成为人与宝可梦和谐共生的生态都市。

然而，随着 Z-A 计划的推进，城市底层——普里兹姆塔地下及南部荒废区——开始出现野生宝可梦**自发超级进化**的异常现象，且失控宝可梦的行为极具攻击性。官方机构 **Team MZ（Méga Zetsubou Research）** 成立，负责调查并控制这一威胁。

与此同时，城市上层举办了年度旗舰竞技活动 **Z-A Royale**，训练师们以 Rank Z 为起点，经由对战晋升，目标是登顶 Rank A 成为城市最强战士。

### 1.4 世界观核心设定

#### 超级进化失控（Berserk Mega Evolution）

正常超级进化需要训练师与宝可梦之间高度的羁绊共鸣，通过mega石触发。然而失控超级进化是一种**无主体、自发性**的超级进化，宝可梦在极度恐惧或愤怒时进入该状态，攻击一切生命体。

失控超级进化的宝可梦表现特征：
- 超级进化形态异常扭曲，带有深紫色能量污染
- 完全无法与训练师建立对话
- 击败后不会直接平息，需要特定手段（Z-A 水晶共鸣）压制

**研究假说**（Team MZ 当前认知）：与大量积聚于城市底层的「X 能量残余」有关——该能量由 X/Y 事件中终极武器遗留。

#### 基格尔德与秩序力量

基格尔德（Zygarde）是秩序与生态系统的守护者，以细胞形式分散于卡洛斯各地。当生态系统遭到严重破坏时，基格尔德的细胞开始聚合，寻找宿主以恢复秩序。

在本作中，基格尔德的细胞因城市中 X 能量的异常集中而加速聚合，其完全形态（Complete Forme）的觉醒同时是游戏最终章的核心事件。

### 2.3 反派：Lysandre（李山德）

| 属性 | 设定 |
|------|------|
| 外形 | 与 X/Y 相比更显苍老，蓄起胡须，穿暗红色长袍；左半脸有终极武器爆炸留下的烧伤 |
| 状态 | X/Y 事件「死亡」后实际被 Z-A 计划的原型研究者秘密救下，在地下管网中恢复 |
| 思想变化 | 原先信奉「世界只容美丽」，经历毁灭与重生后扭曲为「只有宝可梦才是世界真正的主人，人类应退出历史舞台」 |
| 目标 | 利用大量积聚的 X 能量，触发全城失控超级进化，以「宝可梦失控」为由迫使人类撤离露米欧丝城，最终激活基格尔德完全形态作为「新秩序的守护神」 |
| 宝可梦搭档 | 超级骨龙、基格尔德（10% 形态，被其暂时控制）|
| 悲剧性 | 对美的执念未变，却从「毁灭丑陋的世界」演变为「放弃人类、归还世界」——本质上仍是绝望的理想主义者 |

**Lysandre 的三幕弧**：
1. **幕后黑手**（第1-2章）：以「神秘恩人」身份向 Z-A Royale 提供资助，暗中推进 X 能量汇聚实验
2. **真面目披露**（第3章）：玩家发现其未死，对话中呈现其思想转变，形成第一次正面冲突
3. **最终对决**（第5章）：在基格尔德觉醒的地点与玩家展开最后一战，结局因玩家选择产生分歧

## 3. 主线剧情大纲

### 剧情总述

主题：**「在废墟上建造的理想，究竟属于谁？」**

X/Y 事件留下的创伤未曾真正愈合——它只是被璀璨的城市灯光遮盖了。玩家在竞技荣光与城市危机的交织中，逐渐揭开这座城市底层的黑暗真相，并最终面对一个问题：当一个绝望者的理想以毁灭为代价时，如何回应？

### 4.3 对话管理器（Godot 实现）

```gdscript
# dialogue_manager.gd (AutoLoad 单例)
extends Node

signal dialogue_started(dialogue_id: String)
signal dialogue_ended(dialogue_id: String)
signal choice_made(node_id: String, choice_index: int)

var current_dialogue_id: String = ""
var current_node: DialogueData.DialogueNode = null
var current_line_index: int = 0
var is_playing: bool = false

# 对话资源缓存
var dialogue_cache: Dictionary = {}

func start_dialogue(dialogue_id: String) -> void:
    if is_playing:
        push_warning("对话已在播放中: " + current_dialogue_id)
        return
    
    var data = _load_dialogue(dialogue_id)
    if not data:
        push_error("找不到对话数据: " + dialogue_id)
        return
    
    current_dialogue_id = dialogue_id
    is_playing = true
    get_tree().paused = true  # 暂停游戏逻辑
    dialogue_started.emit(dialogue_id)
    _play_node(data.get_node("start"))

func _play_node(node: DialogueData.DialogueNode) -> void:
    current_node = node
    current_line_index = 0
    _play_next_line()

func _play_next_line() -> void:
    if current_line_index >= current_node.lines.size():
        _on_node_complete()
        return
    
    var line = current_node.lines[current_line_index]
    DialogueBox.show_line(line)
    
    # 触发行内事件
    for event_key in line.trigger_events:
        EventSystem.trigger(event_key)
    
    current_line_index += 1

func make_choice(choice_index: int) -> void:
    var choice = current_node.choices[choice_index]
    
    # 设置 Flag
    for flag_key in choice.flag_set:
        FlagManager.set_flag(flag_key, choice.flag_set[flag_key])
    
    choice_made.emit(current_node.node_id, choice_index)
    
    var data = _load_dialogue(current_dialogue_id)
    _play_node(data.get_node(choice.next_node_id))

func _load_dialogue(dialogue_id: String) -> DialogueData:
    if dialogue_cache.has(dialogue_id):
        return dialogue_cache[dialogue_id]
    
    var path = "res://data/dialogues/" + dialogue_id + ".json"
    if not ResourceLoader.exists(path):
        return null
    
    var file = FileAccess.open(path, FileAccess.READ)
    var json_data = JSON.parse_string(file.get_as_text())
    var data = DialogueData.from_json(json_data)
    dialogue_cache[dialogue_id] = data
    return data
```

var rank_points: int = 0

    var opponent_id: String
    var result: String      # "win" / "lose"

    var timestamp: float

func add_points(amount: int) -> void:
    rank_points += amount
    _check_rank_up()
    FlagManager.set_flag("royale_rank_points", rank_points)

func _check_rank_up() -> void:
    var next_rank_idx = RANK_ORDER.find(current_rank) + 1
    if next_rank_idx >= RANK_ORDER.size():
        return
    
    var next_rank = RANK_ORDER[next_rank_idx]
    var threshold = RANK_THRESHOLDS[next_rank]
    
    if threshold != -1 and rank_points >= threshold:
        _promote_rank(next_rank)

func _promote_rank(new_rank: String) -> void:
    var old_rank = current_rank
    current_rank = new_rank
    FlagManager.set_flag("royale_rank", new_rank)
    rank_promoted.emit(old_rank, new_rank)
    # 触发晋级对话/仪式事件
    EventSystem.trigger("ROYALE_RANK_UP_" + new_rank)

signal rank_promoted(old_rank: String, new_rank: String)

# 全局事件注册表
var event_handlers: Dictionary = {}
# 事件历史记录（用于调试与存档验证）
var event_history: Array = []

func register_handler(event_key: String, callable: Callable) -> void:
    if not event_handlers.has(event_key):
        event_handlers[event_key] = []
    event_handlers[event_key].append(callable)

func unregister_handler(event_key: String, callable: Callable) -> void:
    if event_handlers.has(event_key):
        event_handlers[event_key].erase(callable)

func trigger(event_key: String, payload: Dictionary = {}) -> void:
    event_history.append({
        "key": event_key,
        "payload": payload,
        "time": Time.get_ticks_msec()
    })
    
    if not event_handlers.has(event_key):
        return
    
    for handler in event_handlers[event_key]:
        handler.call(payload)

    if not _check_conditions():

## 注意事项与实现风险

### 系统间依赖关系

```
FlagManager ←→ DialogueManager  （对话条件检查与 Flag 设置）
FlagManager ←→ QuestSystem       （任务解锁与完成检测）
FlagManager ←→ WorldStateManager （世界状态响应 Flag 变化）
EventSystem ←→ 所有子系统        （解耦通信总线）
CutsceneController ← EventSystem （过场由事件触发）
RoyaleRankSystem → FlagManager   （排名变化写入 Flag）
```

### 关键实现注意事项

1. **AutoLoad 初始化顺序**：FlagManager → WorldStateManager → EventSystem → DialogueManager → QuestSystem → RoyaleRankSystem。确保依赖项先于使用者初始化。

2. **对话暂停与战斗的冲突**：对话触发时 `get_tree().paused = true`，但战斗系统需要排除在暂停逻辑之外（设置 `process_mode = ALWAYS`）。

3. **存档时机**：强制存档点仅设在章节完成、任务完成、离开区域时，避免玩家在 Flag 设置中途存档导致逻辑不一致。

4. **分支对话的 Flag 原子性**：玩家选择后立即写入 Flag，不依赖对话完整播放完成——防止跳过对话导致 Flag 未设置。

5. **基格尔德细胞收集的容错**：若玩家在 CH4 前未收集到 50 个细胞，系统应提供「应急路线」（AZ 直接提供基格尔德协助），避免主线阻断。

6. **Lysandre 的三个结局分支**：从 CH4 对话选择（A/B/C）开始分叉，但分支在 CH5 前只影响对话内容，不影响关卡结构——直到 CH5-3 才产生实质差异，降低内容制作量。

7. **性能考量**：事件历史记录（`event_history`）在正式发布版本应限制最大长度（建议 500 条），超出后循环覆盖最旧记录，防止内存持续增长。
