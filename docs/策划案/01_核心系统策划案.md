## 1. 角色移动系统

### 1.1 功能描述

玩家控制主角在俯视角2D地图中自由移动，支持8方向行走与奔跑，角色朝向随移动方向实时切换，配合动画状态机播放对应动作。移动系统需兼顾手柄与键盘双输入源，保证操控手感流畅，不产生卡顿或斜向加速问题。

### 1.2 核心参数定义

| 参数名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `walk_speed` | `float` | `80.0` | 行走速度（像素/秒） |
| `run_speed` | `float` | `160.0` | 奔跑速度（像素/秒） |
| `acceleration` | `float` | `800.0` | 加速度（像素/秒²），决定响应灵敏度 |
| `friction` | `float` | `1200.0` | 摩擦力（像素/秒²），决定停止手感 |
| `run_input_action` | `StringName` | `"run"` | 奔跑按键 InputMap 动作名 |
| `diagonal_normalize` | `bool` | `true` | 斜向移动向量归一化开关，防止斜向超速 |

**朝向枚举定义**：

```gdscript
enum Direction {
    DOWN  = 0,  # 默认朝向
    UP    = 1,
    LEFT  = 2,
    RIGHT = 3
}
```

**速度计算逻辑**：

- 目标速度 = 输入向量（归一化）× 当前速度上限
- 实际速度 = `move_toward(velocity, target_velocity, acceleration * delta)` （加速阶段）
- 刹车速度 = `move_toward(velocity, Vector2.ZERO, friction * delta)` （无输入时）

### 1.3 Godot 4 实现思路

**场景结构**：

```
Player (CharacterBody2D)
├── CollisionShape2D          # 碰撞体（胶囊形，脚部对齐）
├── Sprite2D / AnimatedSprite2D  # 角色精灵
├── AnimationPlayer           # 动画控制器
└── camera_anchor (Marker2D)  # 相机挂载锚点（可选）
```

**节点类型选择**：

- 主节点使用 `CharacterBody2D`，配合 `move_and_slide()` 处理碰撞滑动。
- 动画使用 `AnimatedSprite2D` + 帧动画，或 `AnimationPlayer` + `SpriteFrames`，推荐前者在精灵表较规整时使用。

**核心脚本逻辑（player.gd 伪代码）**：

```gdscript
func _physics_process(delta: float) -> void:
    var input_dir := Input.get_vector("move_left", "move_right", "move_up", "move_down")
    var is_running := Input.is_action_pressed("run")
    var target_speed := run_speed if is_running else walk_speed

    if input_dir != Vector2.ZERO:
        velocity = velocity.move_toward(input_dir.normalized() * target_speed, acceleration * delta)
        _update_direction(input_dir)
        _update_animation(is_running)
    else:
        velocity = velocity.move_toward(Vector2.ZERO, friction * delta)
        _play_idle_animation()

    move_and_slide()
```

**信号设计**：

| 信号名 | 参数 | 触发时机 |
|--------|------|----------|
| `direction_changed(new_dir: Direction)` | 新朝向 | 移动朝向切换时 |
| `run_started` | 无 | 开始奔跑时 |
| `run_stopped` | 无 | 停止奔跑时 |
| `movement_stopped` | 无 | 速度归零时 |

### 1.4 注意事项

- **斜向移动归一化**：必须对输入向量调用 `.normalized()`，否则斜向移动速度约为正向的 1.41 倍，体验不一致。
- **动画朝向优先级**：奔跑动画与行走动画共用朝向逻辑，最后一次移动方向决定待机朝向。
- **手柄摇杆死区**：通过 `Input.get_vector()` 的第5个参数设置死区（默认 0.5），避免手柄漂移。
- **斜角动画**：本作采用4方向朝向（上下左右），无单独斜角动画，斜向移动时优先显示横向朝向（左/右），当纵向输入绝对值 > 横向时切换为纵向朝向。
- **Autoload 注意**：玩家节点不建议作为 Autoload，应由场景树统一管理，通过 `get_tree().get_first_node_in_group("player")` 或信号总线获取引用。

## 2. 地图系统

### 2.1 功能描述

以宝可梦 Legends Z-A 的核心舞台"露米欧丝城（Lumiose City）"为蓝本，构建俯视角2D城市地图。地图分区管理，玩家在区域间切换时触发场景加载或区块激活，保证性能与体验的平衡。城市内设置可进入的建筑室内场景，通过出入口节点控制场景跳转。

### 2.2 露米欧丝城分区规划

露米欧丝城以中央放射状路网为特征，按地理位置与功能划分为以下区域：

#### 主要区域列表

| 区域ID | 区域名称 | 类型 | 备注 |
|--------|----------|------|------|
| `zone_central` | 中央广场 | 核心枢纽 | 棱镜塔所在，地图中心，全区域可达 |
| `zone_north` | 北区大道 | 街道 | 连接中央与北出口，精品店聚集 |
| `zone_south` | 南区大道 | 街道 | 连接中央与南出口，训练家聚集 |
| `zone_east` | 东区大道 | 街道 | 连接中央与东出口，宝可梦中心 |
| `zone_west` | 西区大道 | 街道 | 连接中央与西出口，宝可梦研究所 |
| `zone_north_east` | 东北住宅区 | 住宅 | NPC民居，支线任务区域 |
| `zone_north_west` | 西北工坊区 | 功能区 | 道具合成工坊 |
| `zone_south_east` | 东南集市区 | 商业 | 露天市场，道具交易 |
| `zone_south_west` | 西南公园区 | 野外 | 野生宝可梦出没区域 |
| `interior_prism_tower` | 棱镜塔内部 | 室内 | 独立场景，多楼层结构 |
| `interior_pokemon_center` | 宝可梦中心内部 | 室内 | 独立场景，回复/存档点 |
| `interior_shops` | 各商店内部 | 室内 | 多个共用同一模板场景 |

#### 野外/战斗区域

| 区域ID | 区域名称 | 野生宝可梦类型 | 触发方式 |
|--------|----------|--------------|----------|
| `wild_park` | 西南公园 | 草系/虫系 | 踩入高草丛 |
| `wild_underground` | 地下通道 | 岩石系 | 特定入口触发 |

### 2.3 区域切换方式

**三种切换模式**：

| 切换类型 | 适用场景 | 实现节点 |
|----------|----------|----------|
| **无缝切换**（Seamless） | 同一大地图内相邻区域间移动 | `Area2D` 触发器 + 摄像机边界更新 |
| **淡入淡出切换**（Fade） | 进入/离开室内场景 | `Area2D` 触发器 + 全屏黑色遮罩动画 |
| **直接加载**（Load） | 差异极大的独立场景（如棱镜塔） | `SceneTree.change_scene_to_file()` + 加载画面 |

**区域触发器数据结构**：

```gdscript
# zone_transition.gd
class_name ZoneTransition
extends Area2D

@export var target_scene: String = ""        # 目标场景路径
@export var target_spawn_id: String = ""     # 目标出生点ID
@export var transition_type: TransitionType  # 切换类型枚举
@export var require_direction: bool = false  # 是否限制进入方向
@export var entry_direction: Direction = Direction.DOWN  # 允许进入的朝向

enum TransitionType { SEAMLESS, FADE, LOAD }
```

### 2.4 TileMap 层级划分

采用 Godot 4 的 `TileMapLayer`（4.x 推荐用多个 `TileMapLayer` 节点替代单节点多层方案）：

| 层级编号 | 层级名称 | 用途 | 碰撞 | Z-Index |
|----------|----------|------|------|---------|
| Layer 0 | `ground` | 地面底层（石板、草地、水面） | 无 | -10 |
| Layer 1 | `ground_detail` | 地面装饰细节（裂缝、花纹） | 无 | -9 |
| Layer 2 | `collision_walls` | 墙壁与障碍物 | **有** | 0 |
| Layer 3 | `objects_below` | Y轴排序对象（低于角色，如低矮灌木） | 无 | -1 |
| Layer 4 | `objects_above` | Y轴排序对象（高于角色，如树冠） | 无 | +1（动态） |
| Layer 5 | `roof` | 建筑屋顶（进入建筑后隐藏） | 无 | +10 |
| Layer 6 | `overlay` | 覆盖层（天气效果、光影） | 无 | +20 |

**Y-轴排序**：角色与 Layer 3/4 的对象需启用 Y-Sort，通过各节点 `y_sort_enabled = true` 实现角色与场景物件的正确遮挡关系。

### 2.5 Godot 4 实现思路

**场景结构（以 zone_central 为例）**：

```
ZoneCentral (Node2D, y_sort_enabled=true)
├── TileMapLayer_ground
├── TileMapLayer_ground_detail
├── TileMapLayer_collision_walls
├── TileMapLayer_objects_below
├── TileMapLayer_objects_above
├── TileMapLayer_roof
├── ZoneTransitions (Node2D)
│   ├── TransitionToNorth (ZoneTransition/Area2D)
│   ├── TransitionToSouth (ZoneTransition/Area2D)
│   └── ...
├── SpawnPoints (Node2D)
│   ├── SpawnFromNorth (Marker2D)
│   └── ...
├── NPCs (Node2D)
└── WildAreas (Node2D)
    └── WildGrassArea (Area2D)
```

**信号设计**：

| 信号名 | 参数 | 触发时机 |
|--------|------|----------|
| `zone_entered(zone_id: String)` | 区域ID | 玩家进入新区域时 |
| `zone_exited(zone_id: String)` | 区域ID | 玩家离开区域时 |
| `scene_transition_started(target: String)` | 目标场景 | 场景切换开始时 |

**信号总线（EventBus Autoload）**：建议使用全局 Autoload `EventBus` 广播区域切换事件，供小地图、UI、BGM系统等多个系统监听。

### 2.6 注意事项

- **场景分割策略**：露米欧丝城体量较大，建议将整个城市拆分为 3×3 共9个区块场景，以当前玩家所在区块为中心，动态加载相邻8个区块（或仅加载相邻4个），卸载超出范围的区块，避免单场景过重。
- **室内场景独立**：所有室内场景独立为单独 `.tscn` 文件，与室外地图解耦，通过传送节点互联。
- **TileSet 复用**：所有区域共用同一套 `TileSet` 资源（`.tres` 文件），通过不同 `TileMapLayer` 复用，减少资源冗余。
- **屋顶隐藏逻辑**：当玩家进入建筑物碰撞触发区域时，通过信号隐藏对应建筑的 `roof` 层图块（可用 `TileMapLayer.set_layer_enabled(false)` 或整层透明度过渡）。

## 3. 相机系统

### 3.1 功能描述

相机以玩家角色为跟随目标，保持角色在画面中央偏下位置，营造向前探索的视觉感。相机在区域边界处硬限制，防止显示区域外的空白内容。支持特定剧情演出时的相机过场（Cutscene 锁定、平移至目标点）。

### 3.2 核心参数定义

| 参数名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `follow_smoothing` | `float` | `5.0` | 跟随插值速度（`lerp` 系数），值越大跟随越紧 |
| `offset` | `Vector2` | `Vector2(0, -16)` | 相机中心相对角色的偏移（向上偏移，扩大前方视野） |
| `zoom_normal` | `Vector2` | `Vector2(2.0, 2.0)` | 正常游玩缩放（像素游戏常用2倍或3倍） |
| `zoom_battle` | `Vector2` | `Vector2(2.5, 2.5)` | 战斗过渡时临时缩放 |
| `zoom_cutscene` | `Vector2` | `Vector2(1.5, 1.5)` | 剧情演出缩放 |
| `zoom_lerp_speed` | `float` | `3.0` | 缩放插值速度 |
| `boundary_margin` | `float` | `0.0` | 边界内缩余量（像素），防止相机显示边缘外 |

**边界矩形数据结构**：

```gdscript
# camera_boundary.gd
class_name CameraBoundary
extends Resource

@export var region_id: String = ""
@export var limit_left: int = 0
@export var limit_right: int = 1280
@export var limit_top: int = 0
@export var limit_bottom: int = 720
```

### 3.3 Godot 4 实现思路

**场景结构**：

```
Player (CharacterBody2D)
└── PlayerCamera (Camera2D)      # 相机挂载在玩家节点下
    └── (无子节点，逻辑在脚本中)
```

**相机挂载方式**：将 `Camera2D` 作为 Player 的子节点，利用 Godot 4 `Camera2D` 的内置平滑功能（`position_smoothing_enabled`）实现跟随，同时通过 `limit_*` 属性设置边界。

**核心脚本逻辑（player_camera.gd）**：

```gdscript
class_name PlayerCamera
extends Camera2D

@export var zoom_target: Vector2 = Vector2(2.0, 2.0)

func _ready() -> void:
    position_smoothing_enabled = true
    position_smoothing_speed = 5.0
    offset = Vector2(0, -16)
    _apply_zoom(zoom_target)

func set_boundary(boundary: CameraBoundary) -> void:
    limit_left   = boundary.limit_left
    limit_right  = boundary.limit_right
    limit_top    = boundary.limit_top
    limit_bottom = boundary.limit_bottom

func zoom_to(target_zoom: Vector2, duration: float = 0.4) -> void:
    var tween := create_tween()
    tween.tween_property(self, "zoom", target_zoom, duration).set_trans(Tween.TRANS_SINE)

func lock_to_position(world_pos: Vector2, duration: float = 1.0) -> void:
    # 剧情演出：解除父节点跟随，相机移动到指定世界坐标
    set_as_top_level(true)
    var tween := create_tween()
    tween.tween_property(self, "global_position", world_pos, duration)

func release_lock() -> void:
    set_as_top_level(false)
    position = Vector2.ZERO   # 重置为相对父节点偏移
```

**信号设计**：

| 信号名 | 参数 | 触发时机 |
|--------|------|----------|
| `camera_locked` | 无 | 相机锁定至演出点时 |
| `camera_released` | 无 | 相机恢复玩家跟随时 |
| `boundary_changed(new_boundary: CameraBoundary)` | 新边界 | 区域切换时边界更新 |

**区域切换时边界更新流程**：

1. 玩家进入 `ZoneTransition` 触发区域
2. `EventBus` 广播 `zone_entered(zone_id)`
3. `CameraManager`（Autoload）根据 `zone_id` 查表获取 `CameraBoundary` 资源
4. 调用 `PlayerCamera.set_boundary(boundary)` 更新限制

### 3.4 注意事项

- **像素完美渲染**：推荐在项目设置中开启 `rendering/2d/snap/snap_2d_transforms_to_pixel = true` 与 `rendering/2d/snap/snap_2d_vertices_to_pixel = true`，防止像素游戏的亚像素抖动。
- **相机边界与地图尺寸对齐**：`limit_*` 值必须与对应 `TileMapLayer` 的实际像素边界严格对齐，建议通过工具脚本自动计算 `TileMap` 的 `get_used_rect()` 来生成边界数据。
- **缩放与分辨率**：以 320×180（16:9）为基准分辨率，缩放2倍后为 640×360，再由窗口拉伸至目标分辨率。`Camera2D.zoom` 值需与基准分辨率配合，避免模糊。
- **剧情相机恢复**：`lock_to_position()` 调用 `set_as_top_level(true)` 后，结束时必须调用 `release_lock()` 恢复父节点跟随，否则相机会停留在世界空间不再跟随角色。
- **多相机禁用**：场景中同时只能有一个 `current = true` 的相机，切换场景时确保旧相机被正确释放。

## 4. 碰撞系统

### 4.1 功能描述

使用 Godot 4 的物理层（Physics Layer）体系定义游戏内所有碰撞关系，通过"层（Layer）与掩码（Mask）"的组合精确控制哪些物体之间会发生碰撞检测，避免不必要的性能开销，同时保证游戏逻辑的正确性。

### 4.2 碰撞层分类定义

Godot 4 最多支持 32 个物理层，本项目使用前 8 层：

| 层编号 | 层名称 | 使用对象 | 颜色标识（编辑器） |
|--------|--------|----------|------------------|
| Layer 1 | `player` | 玩家角色 CharacterBody2D | 蓝色 |
| Layer 2 | `npc` | NPC CharacterBody2D | 绿色 |
| Layer 3 | `wall` | 墙壁/障碍 TileMapLayer 碰撞体 | 灰色 |
| Layer 4 | `trigger` | 触发区域 Area2D（出入口、剧情触发器） | 黄色 |
| Layer 5 | `wild_zone` | 野生区域 Area2D（战斗触发草丛） | 红色 |
| Layer 6 | `item` | 场景拾取物 Area2D | 橙色 |
| Layer 7 | `projectile` | 投射物（技能特效，预留） | 紫色 |
| Layer 8 | `camera_zone` | 相机边界/区域切换辅助 Area2D | 青色 |

**Layer 命名约定**：在项目设置 `Layer Names > 2D Physics` 中设置对应名称，方便编辑器面板可读。

### 4.3 各层交互规则（碰撞矩阵）

下表中 `O` 表示会发生碰撞/检测，`-` 表示忽略：

|  | player | npc | wall | trigger | wild_zone | item | projectile | camera_zone |
|--|--------|-----|------|---------|-----------|------|------------|-------------|
| **player** | - | O | O | O | O | O | - | O |
| **npc** | O | - | O | - | - | - | - | - |
| **wall** | O | O | - | - | - | - | - | - |
| **trigger** | O | - | - | - | - | - | - | - |
| **wild_zone** | O | - | - | - | - | - | - | - |
| **item** | O | - | - | - | - | - | - | - |
| **projectile** | - | - | O | - | - | - | - | - |
| **camera_zone** | O | - | - | - | - | - | - | - |

**Layer 与 Mask 配置示例**：

```gdscript
# 玩家配置
# Layer = 1 (player)
# Mask  = 2 | 4 | 8 | 16 | 32 | 64 | 256
#       = npc + wall + trigger + wild_zone + item + (skip projectile) + camera_zone

# NPC配置
# Layer = 2 (npc)
# Mask  = 1 | 4
#       = player + wall

# 触发器配置（Area2D）
# Layer = 8 (trigger)
# Mask  = 1
#       = player only
```

### 4.4 特殊交互规则说明

**野生战斗触发（wild_zone）**：

- `WildGrassArea`（Layer 5）设为 `monitoring = true`，监听玩家进入
- 玩家奔跑通过草丛时，触发概率降低（奔跑降低随机遭遇率）
- 触发战斗后，`wild_zone` 的 `monitorable` 临时关闭，战斗结束后重新开启
- 水面/特殊地形的野生区单独设定，不受奔跑修正

**NPC 碰撞**：

- NPC 与玩家之间有碰撞（防止穿模），但 NPC 之间无碰撞（简化寻路逻辑）
- 对话触发通过独立的小范围 `Area2D`（隶属 trigger 层）实现，而非依赖 CharacterBody2D 碰撞

**投射物（预留）**：

- 当前版本战斗为回合制，投射物层仅用于部分技能特效演出，不参与实际伤害碰撞

### 4.5 Godot 4 实现思路

**TileMapLayer 碰撞配置**：

```
TileMapLayer_collision_walls
└── Physics Layer 0:
    collision_layer = 4  (wall, bit 3)
    collision_mask  = 0  (墙壁不主动检测任何物体)
```

**Area2D 触发器模板（zone_trigger.gd）**：

```gdscript
class_name ZoneTrigger
extends Area2D

func _ready() -> void:
    collision_layer = 8   # trigger 层
    collision_mask  = 1   # 仅检测 player
    body_entered.connect(_on_body_entered)

func _on_body_entered(body: Node2D) -> void:
    if body.is_in_group("player"):
        triggered.emit(body)

signal triggered(player: Node2D)
```

**碰撞层常量文件（collision_layers.gd，Autoload 或 static class）**：

```gdscript
class_name CollisionLayers

const PLAYER      : int = 1        # bit 0 -> value 1
const NPC         : int = 1 << 1   # bit 1 -> value 2
const WALL        : int = 1 << 2   # bit 2 -> value 4
const TRIGGER     : int = 1 << 3   # bit 3 -> value 8
const WILD_ZONE   : int = 1 << 4   # bit 4 -> value 16
const ITEM        : int = 1 << 5   # bit 5 -> value 32
const PROJECTILE  : int = 1 << 6   # bit 6 -> value 64
const CAMERA_ZONE : int = 1 << 7   # bit 7 -> value 128
```

### 4.6 注意事项

- **层编号从1开始**：Godot 编辑器中碰撞层编号从1开始，但代码中 `collision_layer` 是位掩码，Layer 1 对应 bit 0（值为1），Layer 2 对应 bit 1（值为2），注意对应关系。
- **Area2D 的 monitoring 与 monitorable 区分**：`monitoring` 控制该区域是否主动检测其他物体进入；`monitorable` 控制该区域是否能被其他区域检测到。触发器通常只需 `monitoring=true`，`monitorable=false`。
- **性能优化**：野生区域 `WildGrassArea` 较大时，考虑将其拆分为多个小 `Area2D` 或使用 `ShapeQuery` 按需检测，避免大面积 Area2D 的持续 overlap 检测开销。
- **调试可视化**：开发阶段在项目设置中开启 `debug/shapes/collision/show_on_top = true`，并为不同层分配不同颜色，方便定位碰撞问题。

## 5. 存档系统

### 5.1 功能描述

玩家在特定存档点手动触发存档，或在区域切换、宝可梦中心等关键节点自动存档。存档数据以 JSON 格式序列化保存至本地文件，支持多存档槽位（最多3个）。读档时完整恢复游戏状态，包括玩家位置、宝可梦队伍、背包道具、任务进度等核心数据。

### 5.2 存档数据结构定义

### 5.4 存档时机

| 存档类型 | 触发条件 | 是否显示提示UI |
|----------|----------|--------------|
| **手动存档** | 玩家在存档点交互，选择确认存档 | 是（存档完成提示） |
| **自动存档** | 进入宝可梦中心治疗后 | 是（角落小提示，3秒消失） |
| **检查点存档** | 通过区域切换到新主要区域时 | 否（静默存档） |
| **剧情节点存档** | 特定剧情演出完成后 | 是（小提示） |

**自动存档不覆盖手动存档槽位**：自动存档使用独立的 `autosave.json`，手动存档管理3个槽位，相互独立。

### 5.6 Godot 4 实现思路

**SaveManager（Autoload 单例）**：

```gdscript
# save_manager.gd
class_name SaveManagerClass
extends Node

const SAVE_DIR := "user://saves/"
const AUTOSAVE_PATH := "user://saves/autosave.json"

var current_save: SaveData = null

func save_to_slot(slot: int) -> bool:
    var data := _collect_game_state()
    data.save_slot = slot
    data.save_time = Time.get_datetime_string_from_system()
    var json_str := JSON.stringify(_save_data_to_dict(data), "\t")
    var file := FileAccess.open(SAVE_DIR + "save_slot_%d.json" % slot, FileAccess.WRITE)
    if file == null:
        push_error("存档失败：无法写入文件")
        return false
    file.store_string(json_str)
    _update_meta(slot, data)
    save_completed.emit(slot)
    return true

func load_from_slot(slot: int) -> bool:
    var path := SAVE_DIR + "save_slot_%d.json" % slot
    if not FileAccess.file_exists(path):
        return false
    var file := FileAccess.open(path, FileAccess.READ)
    var json := JSON.new()
    if json.parse(file.get_as_text()) != OK:
        push_error("读档失败：JSON解析错误")
        return false
    current_save = _dict_to_save_data(json.data)
    _apply_game_state(current_save)
    load_completed.emit(slot)
    return true

func _collect_game_state() -> SaveData:
    # 从各系统收集当前状态
    var data := SaveData.new()
    var player := get_tree().get_first_node_in_group("player")
    data.player_position = player.global_position
    data.current_scene = get_tree().current_scene.scene_file_path
    # ... 收集其他系统数据
    return data

signal save_completed(slot: int)
signal load_completed(slot: int)
signal autosave_completed
```

**信号设计**：

| 信号名 | 参数 | 触发时机 |
|--------|------|----------|
| `save_completed(slot: int)` | 槽位编号 | 存档成功写入后 |
| `load_completed(slot: int)` | 槽位编号 | 读档并应用状态后 |
| `autosave_completed` | 无 | 自动存档完成后 |
| `save_failed(reason: String)` | 失败原因 | 存档写入失败时 |

### 5.7 注意事项

- **`user://` 路径**：在 Godot 4 中，存档文件必须使用 `user://` 路径（而非 `res://`），该路径在不同平台映射到不同目录（Windows 为 `%APPDATA%/Godot/app_userdata/<项目名>/`）。
- **数据序列化一致性**：`Vector2` 无法直接 JSON 序列化，需手动转换为 `{"x": float, "y": float}` 字典，读档时再还原为 `Vector2`。建议封装统一的序列化/反序列化辅助函数。
- **存档完整性校验**：在存档 JSON 中加入版本号字段（`"version": "1.0"`），读档时检查版本兼容性，对旧版存档进行迁移处理，避免版本更新后存档损坏。
- **防存档覆盖确认**：对已有内容的存档槽进行覆盖时，必须弹出确认对话框（"确定覆盖存档X？"），避免玩家误操作。
- **异步存档（可选）**：存档量较大时（含图鉴、大量道具），考虑使用 `Thread` 异步写入文件，防止存档时出现短暂卡顿帧。当前阶段 JSON 文件体量应在可接受范围，优先确保功能正确性。
- **加密（可选）**：正式版本可使用 `FileAccess.open_encrypted_with_pass()` 对存档文件加密，防止玩家修改存档数据作弊。开发阶段使用明文便于调试。
- **存档目录初始化**：游戏启动时（`Main` 场景 `_ready`）检查 `user://saves/` 目录是否存在，不存在则调用 `DirAccess.make_dir_recursive_absolute()` 创建。
