## 1. 宝可梦数据库设计

### 1.1 功能描述

宝可梦数据库是整个宝可梦系统的基础，负责存储所有宝可梦的静态数据（种族数据）以及运行时的动态数据（个体数据）。静态数据通过 Godot 4 的 `Resource` 体系持久化，动态数据则在实例化时生成，支持存档读写。

数据库设计遵循**数据与逻辑分离**原则：
- **静态种族数据**（PokemonSpeciesData）：不可变，描述该种宝可梦的基础属性
- **动态个体数据**（PokemonInstance）：可变，描述某只具体宝可梦的当前状态
- **技能数据**（MoveData）：独立维护，供宝可梦种族与个体共同引用

```gdscript
## ── 状态异常 ──────────────────────────────
@export var status: PokemonEnums.StatusCondition = PokemonEnums.StatusCondition.NONE
@export var toxic_counter: int = 0          # 剧毒层数
@export var sleep_turns: int = 0            # 睡眠剩余回合数

## ── 持有道具 ──────────────────────────────
@export var held_item_id: int = -1          # 持有道具ID（-1=无）

## ── 训练师信息 ────────────────────────────
@export var original_trainer_name: String = ""
@export var original_trainer_id: int = 0
@export var is_traded: bool = false         # 是否为交换获得（影响服从度）

## ── 亲密度 ────────────────────────────────
@export var friendship: int = 70

@export var is_mega_evolved: bool = false
var mega_species_data: PokemonSpeciesData   # 超级进化时的临时种族数据

## 计算最终能力值（含性格修正）
func calculate_stats() -> void:
    if not species_data:
        return
    max_hp = _calc_hp()
    attack = _calc_stat(species_data.base_attack, iv_attack, ev_attack)
    defense = _calc_stat(species_data.base_defense, iv_defense, ev_defense)
    sp_attack = _calc_stat(species_data.base_sp_attack, iv_sp_attack, ev_sp_attack)
    sp_defense = _calc_stat(species_data.base_sp_defense, iv_sp_defense, ev_sp_defense)
    speed = _calc_stat(species_data.base_speed, iv_speed, ev_speed)
    _apply_nature_modifier()

func _calc_hp() -> int:
    # HP专用公式：floor((2*base + iv + floor(ev/4)) * level / 100) + level + 10
    var base := species_data.base_hp
    return int(floor((2.0 * base + iv_hp + floor(ev_hp / 4.0)) * level / 100.0)) + level + 10

func _calc_stat(base: int, iv: int, ev: int) -> int:
    # 普通能力值公式：floor((floor((2*base + iv + floor(ev/4)) * level / 100) + 5))
    return int(floor(floor((2.0 * base + iv + floor(ev / 4.0)) * level / 100.0) + 5.0))

func _apply_nature_modifier() -> void:
    var nm := NatureTable.get_modifier(nature_id)
    attack = int(attack * nm.attack_mult)
    defense = int(defense * nm.defense_mult)
    sp_attack = int(sp_attack * nm.sp_attack_mult)
    sp_defense = int(sp_defense * nm.sp_defense_mult)
    speed = int(speed * nm.speed_mult)

func get_display_name() -> String:
    return nickname if nickname != "" else species_data.species_name if species_data else "???"
```

#### 全局数据库单例

```gdscript
# res://autoloads/PokemonDatabase.gd
extends Node

var _species_cache: Dictionary = {}        # { species_id: PokemonSpeciesData }
var _is_loaded: bool = false

func _ready() -> void:
    _load_all_species()

func _load_all_species() -> void:
    # 使用 ResourceLoader 异步预加载全部种族数据
    var dir := DirAccess.open("res://data/species/db/")
    if not dir:
        return
    dir.list_dir_begin()
    var file_name := dir.get_next()
    while file_name != "":
        if file_name.ends_with(".tres"):
            var res: PokemonSpeciesData = load("res://data/species/db/" + file_name)
            if res:
                _species_cache[res.species_id] = res
        file_name = dir.get_next()
    _is_loaded = true

func get_species(species_id: int) -> PokemonSpeciesData:
    return _species_cache.get(species_id, null)

func create_pokemon(species_id: int, level: int) -> PokemonInstance:
    var instance := PokemonInstance.new()
    instance.species_id = species_id
    instance.species_data = get_species(species_id)
    instance.level = level
    PokemonFactory.randomize_ivs(instance)
    PokemonFactory.assign_nature(instance)
    PokemonFactory.learn_level_moves(instance)
    instance.calculate_stats()
    instance.current_hp = instance.max_hp
    return instance
```

### 1.4 Godot 4 实现思路

- **Resource 热重载**：开发阶段修改 `.tres` 文件后，Godot 4 会自动重载，无需重启编辑器
- **自定义 ResourceFormatLoader**：若数据量大（如完整807种），可自定义 JSON → Resource 的加载器，用 JSON 批量维护数据，运行时转为 Resource
- **ResourcePreloader 节点**：战斗场景中将常用技能和图鉴数据预加载入节点，避免战中卡顿
- **类型安全数组**：`Array[LearnableMove]` 利用 GDScript 4 的类型化数组，降低运行时类型错误

### 1.5 注意事项

- 种族编号与全国图鉴编号保持一致，便于与官方数据对照
- `species_data` 字段在 `PokemonInstance` 中不导出（`@export`），运行时通过 `PokemonDatabase.get_species()` 填充，避免存档文件中存储冗余数据
- 能力值计算必须在每次 EV/IV/等级变更后重新调用 `calculate_stats()`
- 超级进化形态使用独立的 `PokemonSpeciesData` 条目，编号建议用 10001~10xxx 段（参考官方方案）

## 2. 队伍管理系统

### 2.1 功能描述

队伍管理系统负责管理玩家随身携带的最多 6 只宝可梦，支持排序、替换、状态查看、道具操作等。队伍数据随存档持久化，战斗系统和野外交互均依赖本系统。

主要功能模块：
- **队伍容量**：最多 6 只，至少保留 1 只（防止队伍清空）
- **队伍 UI**：队伍选择界面、详细状态界面、技能管理界面
- **宝可梦状态显示**：HP 条、PP 显示、状态异常图标、持有道具
- **道具操作**：给宝可梦持有/取下道具
- **宝可梦排序**：拖拽交换位置

### 2.2 核心数据结构

#### 队伍数据

```gdscript
# res://systems/party/PartyData.gd
class_name PartyData
extends Resource

const MAX_PARTY_SIZE: int = 6

@export var members: Array[PokemonInstance] = []  # 最多6只

func add_pokemon(pokemon: PokemonInstance) -> bool:
    if members.size() >= MAX_PARTY_SIZE:
        return false
    members.append(pokemon)
    return true

func remove_pokemon(index: int) -> PokemonInstance:
    if index < 0 or index >= members.size():
        return null
    if members.size() <= 1:
        push_warning("队伍中至少需要保留1只宝可梦")
        return null
    return members.pop_at(index)

func swap_positions(index_a: int, index_b: int) -> void:
    if index_a < 0 or index_b < 0:
        return
    if index_a >= members.size() or index_b >= members.size():
        return
    var temp := members[index_a]
    members[index_a] = members[index_b]
    members[index_b] = temp

func get_first_healthy() -> PokemonInstance:
    # 获取第一只HP大于0的宝可梦（用于战斗前置派出）
    for member in members:
        if member.current_hp > 0:
            return member
    return null

func is_all_fainted() -> bool:
    return members.all(func(m): return m.current_hp <= 0)

func heal_all() -> void:
    # 宝可梦中心全体恢复
    for member in members:
        member.current_hp = member.max_hp
        member.status = PokemonEnums.StatusCondition.NONE
        member.toxic_counter = 0
        member.sleep_turns = 0
        for i in member.move_pp.size():
            member.move_pp[i] = member.move_max_pp[i]
```

#### HP/PP 状态显示组件

```gdscript
# res://ui/party/HPBar.gd
class_name HPBar
extends Control

@onready var bar: ProgressBar = $ProgressBar
@onready var hp_label: Label = $HPLabel
@onready var status_icon: TextureRect = $StatusIcon

var _pokemon: PokemonInstance

func setup(pokemon: PokemonInstance) -> void:
    _pokemon = pokemon
    refresh()

func refresh() -> void:
    if not _pokemon:
        return
    var ratio := float(_pokemon.current_hp) / float(_pokemon.max_hp)
    bar.value = ratio * 100.0
    hp_label.text = "%d / %d" % [_pokemon.current_hp, _pokemon.max_hp]
    # 根据HP比例变色
    if ratio > 0.5:
        bar.modulate = Color(0.2, 0.8, 0.2)    # 绿色
    elif ratio > 0.25:
        bar.modulate = Color(1.0, 0.8, 0.0)    # 黄色
    else:
        bar.modulate = Color(0.9, 0.1, 0.1)    # 红色
    # 状态异常图标
    _update_status_icon()

func _update_status_icon() -> void:
    var status_textures := {
        PokemonEnums.StatusCondition.BURN: preload("res://assets/ui/status/burn.png"),
        PokemonEnums.StatusCondition.FREEZE: preload("res://assets/ui/status/freeze.png"),
        PokemonEnums.StatusCondition.PARALYSIS: preload("res://assets/ui/status/paralysis.png"),
        PokemonEnums.StatusCondition.POISON: preload("res://assets/ui/status/poison.png"),
        PokemonEnums.StatusCondition.TOXIC: preload("res://assets/ui/status/toxic.png"),
        PokemonEnums.StatusCondition.SLEEP: preload("res://assets/ui/status/sleep.png"),
    }
    if _pokemon.status in status_textures:
        status_icon.texture = status_textures[_pokemon.status]
        status_icon.show()
    else:
        status_icon.hide()
```

## 3. 野生遭遇系统

### 3.1 功能描述

野生遭遇系统控制玩家在野外移动时触发宝可梦战斗的逻辑，包括遭遇区域配置、出现概率分布、等级范围、遭遇触发判定。参考《传说 Z-A》风格：野生宝可梦以实体形式存在于场景中（非随机步数触发），玩家接触或攻击即触发战斗。

遭遇方式分为两类：
- **草丛随机遭遇**：进入草丛区域后按概率触发（兼容性设计，可选）
- **实体野生宝可梦**：宝可梦作为独立 NPC 实体存在于地图，可视化追逃，接触触发战斗

### 3.3 遭遇触发逻辑

```gdscript
# res://systems/encounter/EncounterManager.gd
class_name EncounterManager
extends Node

## 草丛随机遭遇触发
func try_trigger_grass_encounter(area_id: String, player_pos: Vector2) -> void:
    var area_data: WildAreaData = EncounterDatabase.get_area(area_id)
    if not area_data:
        return
    if area_data.method != WildAreaData.EncounterMethod.GRASS:
        return
    # 时间检查
    if not _check_time(area_data.time_restrictions):
        return
    # 概率判定
    if randf() > area_data.encounter_rate:
        return
    # 加权随机选取宝可梦
    var entry := _weighted_random(area_data.encounter_table)
    if not entry:
        return
    var level := randi_range(entry.min_level, entry.max_level)
    var wild_pokemon := PokemonDatabase.create_pokemon(entry.species_id, level)
    # 触发战斗
    BattleManager.start_wild_battle(wild_pokemon)

func _weighted_random(table: Array[EncounterEntry]) -> EncounterEntry:
    var total_weight := 0
    for entry in table:
        total_weight += entry.weight
    var roll := randi_range(0, total_weight - 1)
    var cumulative := 0
    for entry in table:
        cumulative += entry.weight
        if roll < cumulative:
            return entry
    return null

func _check_time(restrictions: Array[String]) -> bool:
    if restrictions.is_empty():
        return true
    var current_time := TimeManager.get_time_of_day()  # "day"/"dusk"/"night"
    return current_time in restrictions
```

### 3.4 Godot 4 实现思路

- **Area2D 触发区**：草丛区域用 `Area2D` + `CollisionShape2D` 标记，玩家进入区域时 `EncounterManager` 开始监听玩家步数/移动
- **实体宝可梦行为树**：`WildPokemonEntity` 使用简单状态机（idle/roam/chase/flee），复杂 AI 可接入 Godot 4 的 `NavigationAgent2D`
- **实体重生系统**：地图重新加载（从其他区域回来）后重置野生实体，通过 `WorldManager` 维护"已捕捉/已击败"的实体列表避免无限刷新
- **天气系统集成**：`EncounterManager` 监听 `WeatherManager.weather_changed` 信号，动态切换遭遇表

### 3.5 注意事项

- 加权随机选取时权重之和不要超过 `int` 范围，建议总权重保持在 100~500 之间
- 实体野生宝可梦必须在被玩家攻击或接触后立即标记"已接触"，防止同一实体触发两次战斗
- 洞窟和夜间遭遇率通常高于草丛（0.15~0.2 vs 0.1~0.15）
- 稀有宝可梦权重设为 1~5，常见宝可梦权重设为 20~40，保持合理稀有度分布

### 4.3 捕捉率公式

使用第六世代（XY/ORAS）标准公式：

```gdscript
# res://systems/capture/CaptureSystem.gd
class_name CaptureSystem
extends Node

## 主判定函数
## 返回值：晃动次数（0~3），3次=捕捉成功
static func calculate_catch_result(
    target: PokemonInstance,
    ball: PokeballData,
    current_turn: int,
    pokedex: PokedexData
) -> int:
    # 大师球直接成功
    if ball.special_type == 5:  # always_catch
        return 3

    # 步骤1：计算修正后捕捉率 a
    var catch_rate_base: float = _get_effective_catch_rate(target, ball, current_turn, pokedex)

    # 步骤2：HP修正
    # a = floor((3 * max_hp - 2 * current_hp) * catch_rate_base / (3 * max_hp))
    var a: float = floor(
        (3.0 * target.max_hp - 2.0 * target.current_hp)
        * catch_rate_base
        / (3.0 * target.max_hp)
    )

    # 步骤3：状态修正
    a *= _get_status_bonus(target.status)
    a = clamp(a, 1.0, 255.0)

    # 步骤4：阈值 b = 1048560 / sqrt(sqrt(16711680 / a))
    var b: float = 1048560.0 / sqrt(sqrt(16711680.0 / a))

    # 步骤5：4次随机判定（每次生成0~65535随机数，小于b则成功一次）
    var shake_count: int = 0
    for _i in range(4):
        var roll := randi_range(0, 65535)
        if roll < int(b):
            shake_count += 1
        else:
            break  # 失败则停止后续判定

    return shake_count  # 0=0次晃动，3=3次晃动但最终失败，4会被判为成功（此处用<4判定）

## 注意：shake_count == 4 才是捕捉成功，但公式中返回0-3，需在调用处用 == 3 判定"跑出"

static func _get_effective_catch_rate(
    target: PokemonInstance,
    ball: PokeballData,
    turn: int,
    pokedex: PokedexData
) -> float:
    var base_rate: float = target.species_data.catch_rate
    match ball.special_type:
        0:  # 普通倍率
            return base_rate * ball.catch_rate_modifier
        1:  # 基于HP（快递球：回合少倍率高）
            var mult := clamp(4.0 - (turn - 1) * (3.0 / 10.0), 1.0, 4.0)
            return base_rate * mult
        2:  # 基于属性（潜水球、黑色球等）
            var types := ball.special_param.split(",")
            var pokemon_types := [target.species_data.type1]
            if target.species_data.has_secondary_type:
                pokemon_types.append(target.species_data.type2)
            for t in pokemon_types:
                if PokemonEnums.ElementType.keys()[t].to_lower() in types:
                    return base_rate * ball.catch_rate_modifier
            return base_rate
        3:  # 基于状态（梦境球）
            var statuses := ball.special_param.split(",")
            var status_str := PokemonEnums.StatusCondition.keys()[target.status].to_lower()
            if status_str in statuses:
                return base_rate * ball.catch_rate_modifier
            return base_rate
        4:  # 基于回合（计时球）
            var mult := min(1.0 + (turn - 1) * (1229.0 / 4096.0), 4.0)
            return base_rate * mult
        _:
            return base_rate * ball.catch_rate_modifier

static func _get_status_bonus(status: PokemonEnums.StatusCondition) -> float:
    match status:
        PokemonEnums.StatusCondition.SLEEP, PokemonEnums.StatusCondition.FREEZE:
            return 2.5
        PokemonEnums.StatusCondition.BURN, PokemonEnums.StatusCondition.POISON, \
        PokemonEnums.StatusCondition.TOXIC, PokemonEnums.StatusCondition.PARALYSIS:
            return 1.5
        _:
            return 1.0
```

### 4.4 捕捉动画流程

```
捕捉流程状态机（BattleCaptureAnimator）:

IDLE
  → [玩家选择精灵球] → THROW_BALL
THROW_BALL（精灵球飞出动画，约0.5s）
  → ABSORB_POKEMON（宝可梦缩小并吸入精灵球，约0.8s）
ABSORB_POKEMON
  → BALL_FALL（精灵球落地滚动，约0.3s）
BALL_FALL
  → [判定晃动次数 shake_count] → SHAKE_LOOP
SHAKE_LOOP（每次晃动0.6s，最多3次）
  → [shake_count >= 3] → CAPTURE_SUCCESS（捕获！音效+闪光+进入图鉴）
  → [shake_count < 3] → CAPTURE_FAIL（宝可梦破球而出）
CAPTURE_FAIL
  → [野生宝可梦HP≤0 或 对方选择逃跑] → BATTLE_END
  → [继续战斗] → IDLE
```

```gdscript
# res://systems/capture/BattleCaptureAnimator.gd
class_name BattleCaptureAnimator
extends Node

signal capture_succeeded(pokemon: PokemonInstance)
signal capture_failed(shake_count: int)

@onready var ball_sprite: Sprite2D = $BallSprite
@onready var tween: Tween

var _pokemon: PokemonInstance
var _ball_data: PokeballData

func play_capture_sequence(
    pokemon: PokemonInstance,
    ball: PokeballData,
    shake_count: int
) -> void:
    _pokemon = pokemon
    _ball_data = ball
    ball_sprite.texture = ball.sprite

    tween = create_tween().set_sequential()
    # 飞出
    tween.tween_method(_animate_throw, 0.0, 1.0, 0.5)
    # 吸入
    tween.tween_method(_animate_absorb, 0.0, 1.0, 0.8)
    # 落地
    tween.tween_method(_animate_fall, 0.0, 1.0, 0.3)
    # 晃动
    for i in shake_count:
        tween.tween_method(_animate_shake, 0.0, 1.0, 0.6)
    # 结果
    tween.tween_callback(_on_animation_complete.bind(shake_count >= 3))

func _on_animation_complete(success: bool) -> void:
    if success:
        capture_succeeded.emit(_pokemon)
    else:
        capture_failed.emit(-1)
```

### 4.5 失败逃跑逻辑

```gdscript
# 野战中玩家尝试逃跑的判定
static func can_player_flee(player_pokemon: PokemonInstance, wild_pokemon: PokemonInstance) -> bool:
    # 公式：逃跑概率 = (我方速度 * 32 / 野生速度 + 30) * 逃跑次数 / 256
    # 若结果 >= 255 则必定成功
    var flee_attempts: int = BattleManager.get_flee_attempts()
    var my_speed := player_pokemon.speed
    var wild_speed := wild_pokemon.speed
    if wild_speed == 0:
        return true
    var rate := int((float(my_speed) * 32.0 / wild_speed + 30.0) * flee_attempts) % 256
    return rate >= 255 or randi_range(0, 255) < rate
```

### 4.6 Godot 4 实现思路

- **捕捉流程作为战斗子状态机**：`BattleStateMachine` 中新增 `STATE_CAPTURE` 状态，由 `BattleCaptureAnimator` 全权控制动画和判定
- **精灵球飞出使用 `Tween`**：Godot 4 的 `Tween.tween_property()` 配合贝塞尔曲线实现弧线飞行效果
- **捕捉结果异步通知**：`capture_succeeded` 信号触发后，由 `BattleManager` 处理：将宝可梦加入队伍/存到PC、写入图鉴、更新存档

### 4.7 注意事项

- 捕捉判定应在动画播放前完成（预计算 shake_count），避免网络同步问题（若未来支持联机）
- 梦境球（255倍）可直接使 `a` 溢出到 255 上限，需用 `clamp` 处理
- 捕捉成功后必须立即将宝可梦实例的 `pokeball_id`、`met_location`、`met_level` 写入
- 大师球不应在正常游戏进程中轻易获得，建议仅作为剧情奖励（单件）

## 5. 图鉴系统

图鉴系统追踪玩家对每种宝可梦的见过/捕捉状态，提供图鉴浏览 UI 和完成度统计。参考《Z-A》风格，图鉴与路亚城重建进度相结合，完成度解锁城市功能。

```gdscript
        # 根据性别随机（实例生成时确定）更新性别见过记录
        pass
    if pokemon.is_shiny:
        entry.seen_shiny = true
    if pokemon.is_mega_evolved:
        entry.seen_mega = true

func catch_pokemon(pokemon: PokemonInstance) -> void:
    see_pokemon(pokemon)
    var entry := _get_or_create_entry(pokemon.species_id)
    entry.is_caught = true
    if pokemon.is_shiny:
        entry.caught_shiny = true

func is_caught(species_id: int) -> bool:
    var entry: PokedexEntry = entries.get(species_id, null)
    return entry.is_caught if entry else false

func is_seen(species_id: int) -> bool:
    var entry: PokedexEntry = entries.get(species_id, null)
    return entry.is_seen if entry else false

func get_completion_stats() -> Dictionary:
    var seen_count := 0
    var caught_count := 0
    var total := PokemonDatabase.get_total_species_count()
    for id in entries:
        var e: PokedexEntry = entries[id]
        if e.is_seen:
            seen_count += 1
        if e.is_caught:
            caught_count += 1
    return {
        "seen": seen_count,
        "caught": caught_count,
        "total": total,
        "seen_pct": float(seen_count) / total * 100.0,
        "caught_pct": float(caught_count) / total * 100.0
    }

func _get_or_create_entry(species_id: int) -> PokedexEntry:
    if species_id not in entries:
        var new_entry := PokedexEntry.new()
        new_entry.species_id = species_id
        entries[species_id] = new_entry
    return entries[species_id]
```

### 5.4 Godot 4 实现思路

- **虚拟列表优化**：宝可梦数量多时（807+），`GridContainer` 需配合 `ScrollContainer` 实现虚拟滚动，只实例化可视范围内的卡片（Godot 4 可通过 `Control.get_global_rect()` 判断可视性）
- **剪影效果**：未捕捉但已见过的宝可梦显示黑色剪影，通过 `CanvasItem.material` 应用自定义 `ShaderMaterial`（将 RGB 全设为 0，保留 Alpha）
- **信号驱动更新**：`PokedexData` 定义 `entry_updated(species_id)` 信号，图鉴 UI 监听后刷新对应卡片
- **搜索防抖**：搜索框使用 `text_changed` 信号配合 `Timer` 实现 300ms 防抖，避免每键入一字符就刷新整个列表

### 5.5 注意事项

- 见过记录应在战斗开始时立即写入，而非战斗结束后，防止游戏崩溃导致丢失记录
- 图鉴编号显示格式统一为三位数补零（`"%03d" % species_id`）
- 超级进化形态在图鉴中作为同一词条的形态子页，而非独立词条，避免编号混乱
- 完成度里程碑（如见过50种/捕捉100种）触发特殊对话或奖励，需在 `get_completion_stats()` 调用后检查里程碑阈值

## 6. 超级进化系统

### 6.1 功能描述

超级进化（Mega Evolution）系统是本游戏的核心特色机制之一，对标《宝可梦传说 Z-A》中以路亚城为背景的超进传说。系统包含：

- **Mega Energy 收集机制**：取代超进化石道具，通过探索卢米欧斯城区域收集对应能量
- **触发条件**：玩家持有超进化手环（Key Stone），宝可梦持有对应 Mega 石，战斗中消耗 Mega Energy 激活
- **变身数据结构**：超级进化形态作为独立种族数据，覆盖能力值、特性、属性
- **战斗限制**：每场战斗只能超进化1次，形态在战斗结束后恢复

---

### 6.2 Mega Energy 收集机制

```gdscript
# res://systems/mega/MegaEnergyData.gd
class_name MegaEnergyData
extends Resource

## Mega Energy 全局存储（随存档持久化）
## key = species_id（基础形态），value = 当前能量值
@export var energy_pool: Dictionary = {}

## 各宝可梦解锁超进化所需能量上限
const UNLOCK_THRESHOLD: int = 100   # 初次解锁需100点
const BATTLE_COST: int = 10         # 每次战斗使用消耗10点（解锁后每次重充至少需有10点）

func add_energy(species_id: int, amount: int) -> void:
    var current: int = energy_pool.get(species_id, 0)
    energy_pool[species_id] = min(current + amount, 999)    # 上限999

func get_energy(species_id: int) -> int:
    return energy_pool.get(species_id, 0)

func can_use_mega(species_id: int) -> bool:
    return get_energy(species_id) >= BATTLE_COST

func use_mega_energy(species_id: int) -> bool:
    if not can_use_mega(species_id):
        return false
    energy_pool[species_id] -= BATTLE_COST
    return true

func is_mega_unlocked(species_id: int) -> bool:
    ## 是否已解锁（累计收集过≥100点即算永久解锁）
    ## 此处用持久化flag更准确，但简化用能量≥0且有过收集记录
    return species_id in energy_pool
```

**能量获取途径**：
| 途径 | 获取量 | 备注 |
|------|--------|------|
| 探索卢米欧斯城特定区域（光点） | 5~15 | 每日刷新 |
| 击败对应超进化形态的宝可梦 | 20 | 特定剧情敌人 |
| 区域复兴任务奖励 | 50 | 一次性 |
| 参加超级进化实验室研究 | 10/次 | 每日限1次 |

### 6.3 触发条件与战斗集成

```gdscript
# res://systems/mega/MegaEvolutionSystem.gd
class_name MegaEvolutionSystem
extends Node

signal mega_evolution_started(pokemon: PokemonInstance)
signal mega_evolution_completed(pokemon: PokemonInstance)
signal mega_evolution_reverted(pokemon: PokemonInstance)

var _has_mega_evolved_this_battle: bool = false

## 检查是否可以在战斗中超进化
func can_trigger_mega(pokemon: PokemonInstance, energy_data: MegaEnergyData) -> bool:
    if _has_mega_evolved_this_battle:
        return false  # 每场战斗只能超进化一次
    if not pokemon.species_data.can_mega_evolve:
        return false
    if pokemon.held_item_id != pokemon.species_data.mega_stone_item_id:
        return false  # 未持有对应Mega石
    if not energy_data.can_use_mega(pokemon.species_id):
        return false  # 能量不足
    return true

## 执行超进化
func trigger_mega_evolution(pokemon: PokemonInstance, energy_data: MegaEnergyData) -> void:
    if not can_trigger_mega(pokemon, energy_data):
        return
    energy_data.use_mega_energy(pokemon.species_id)
    _has_mega_evolved_this_battle = true
    mega_evolution_started.emit(pokemon)
    # 加载超级进化形态数据
    var mega_data := PokemonDatabase.get_species(pokemon.species_data.mega_species_id)
    if not mega_data:
        push_error("超级进化形态数据未找到: %d" % pokemon.species_data.mega_species_id)
        return
    pokemon.mega_species_data = mega_data
    pokemon.is_mega_evolved = true
    # 重新计算能力值（使用超进化种族值）
    var original_species := pokemon.species_data
    pokemon.species_data = mega_data
    pokemon.calculate_stats()
    # 保持HP比例（超进化不会恢复HP，但max_hp变化后需调整current_hp上限）
    pokemon.current_hp = min(pokemon.current_hp, pokemon.max_hp)
    pokemon.species_data = original_species  # 恢复引用，mega_species_data保存超进数据
    mega_evolution_completed.emit(pokemon)

## 战斗结束后恢复
func revert_mega_evolution(pokemon: PokemonInstance) -> void:
    if not pokemon.is_mega_evolved:
        return
    pokemon.is_mega_evolved = false
    pokemon.mega_species_data = null
    pokemon.calculate_stats()  # 恢复原始种族值
    # HP不超过恢复后的最大HP
    pokemon.current_hp = min(pokemon.current_hp, pokemon.max_hp)
    mega_evolution_reverted.emit(pokemon)

func reset_battle_flag() -> void:
    _has_mega_evolved_this_battle = false
```

### 6.7 Godot 4 实现思路

- **超进化形态热切换**：战斗中切换 `pokemon.species_data` 引用（临时换成超进形态数据）来驱动战斗计算，战后恢复引用，无需修改 `PokemonInstance` 核心字段
- **Mega Energy UI**：战斗界面右上角显示当前选中宝可梦的 Mega Energy 进度条，使用 `ProgressBar` + 专属 `StyleBox` 实现能量感图案
- **Key Stone 视觉**：主角战斗模型或 UI 角落常驻显示 Key Stone 装饰，超进化时触发 `AnimationPlayer` 播放专属发光序列
- **每场战斗限制**：`MegaEvolutionSystem._has_mega_evolved_this_battle` 在 `BattleManager.battle_ended` 信号触发时通过 `reset_battle_flag()` 重置

### 6.8 注意事项

- 超进化期间 `pokemon.species_data` 被临时替换，所有访问种族数据的代码（如属性计算、技能判定）均会自动使用超进化数据，无需特殊分支
- 超进化后 HP 不会恢复，但由于 `max_hp` 增大，`current_hp` 应保持不变（允许 current_hp < max_hp 的差值扩大）
- 超进化形态的特性强制替换为专属特性，无视原宝可梦的 `ability_slot`
- Mega Energy 收集进度应做每日重置（除区域探索光点外，战斗/任务奖励不重置），通过 `TimeManager` 比较日期实现
- 甲贺忍蛙的羁绊现象（Battle Bond）需单独维护"羁绊值"计数器，击倒敌方宝可梦时增加，达到阈值触发变身，不消耗 Mega Energy
