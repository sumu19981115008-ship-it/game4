## 1. 战斗场景结构

### 1.1 功能描述

战斗场景是玩家与野生宝可梦或训练家宝可梦进行回合制对战的核心界面。整体风格参考 Legends Z-A 的沉浸式战斗画面，保留传统 2D 精灵图呈现方式，同时提供清晰的信息展示区域与操作响应面板。

#### 精灵图位置

### 1.4 Godot 4 实现思路

```
BattleScene (Node2D)
├── Background (Sprite2D)            ← 场景背景
├── EnemyPlatform (Sprite2D)
├── PlayerPlatform (Sprite2D)
├── EnemySprite (AnimatedSprite2D)
├── PlayerSprite (AnimatedSprite2D)
├── UI (CanvasLayer)
│   ├── EnemyInfoPanel (Control)
│   │   ├── EnemyNameLabel
│   │   ├── EnemyHPBar (TextureProgressBar)
│   │   └── EnemyStatusLabel
│   ├── PlayerInfoPanel (Control)
│   │   ├── PlayerNameLabel
│   │   ├── PlayerHPBar
│   │   ├── PlayerHPLabel ("000/000")
│   │   └── PPIcons (HBoxContainer)
│   ├── BattleLog (RichTextLabel)
│   └── ActionPanel (Control)
│       ├── MainMenu (GridContainer)   ← 战斗/包/宝可梦/逃跑
│       └── MoveMenu (GridContainer)  ← 4 个技能按钮
└── BattleManager (Node)             ← 战斗逻辑控制器
```

**信号流**：
- `BattleManager` 通过信号驱动 UI 更新，UI 不直接操作数据
- 玩家输入通过 `InputEvent` 传递给 `BattleManager`，不直接触发伤害计算

### 1.5 注意事项

- 分辨率基准建议 1280×720，使用 `CanvasLayer` 确保 UI 不随相机移动
- 战斗背景应支持场景差异化（城市/草地/洞穴），使用 `Resource` 预设不同配置
- 精灵图推荐尺寸：96×96 或 128×128（根据美术资源决定），保持 pixel-perfect

## 2. 回合制逻辑

### 2.1 功能描述

采用经典宝可梦回合制战斗框架：双方同时选择行动，再根据优先度与速度决定执行顺序。每回合包含"输入阶段"和"执行阶段"两个主要阶段。

### 2.2 行动类型

```gdscript
enum ActionType {
    FIGHT,      # 使用技能
    BAG,        # 使用道具
    POKEMON,    # 更换宝可梦
    RUN         # 逃跑（仅限野生战）
}

class BattleAction:
    var actor: Pokemon        # 行动者
    var action_type: ActionType
    var move: MoveData        # 若为 FIGHT
    var item: ItemData        # 若为 BAG
    var target_slot: int      # 若为 POKEMON，目标队伍槽位
```

### 2.3 行动优先度系统

#### 优先度等级

| 优先度 | 典型技能 | 说明 |
|--------|----------|------|
| +6 | 守住 | 最高优先级 |
| +4 | 追打、影子偷袭 | — |
| +3 | 神速、子弹拳 | — |
| +1 | 电光石火、恶意把持 | — |
| 0 | 大多数普通技能 | 按速度排序 |
| -1 | 反击 | — |
| -3 | 吞食 | — |
| -6 | 怪力 | 最低优先级 |

**特殊规则**：
- 换宝可梦行动始终在技能之前执行（视为优先度 +6）
- 道具使用优先度 +5（早于大多数攻击技能）
- 逃跑行动不参与优先度排序（直接跳出战斗流程）

#### 速度排序公式

```
有效速度 = 基础速度 × 速度等级系数 × 道具加成 × 状态加成
```

速度等级系数（-6 到 +6）：

| 等级 | 系数 |
|------|------|
| -6 | 2/8 |
| -5 | 2/7 |
| -4 | 2/6 |
| -3 | 2/5 |
| -2 | 2/4 |
| -1 | 2/3 |
| 0 | 2/2 = 1.0 |
| +1 | 3/2 |
| +2 | 4/2 |
| +3 | 5/2 |
| +4 | 6/2 |
| +5 | 7/2 |
| +6 | 8/2 |

麻痹状态：速度 × 0.5（第九世代调整后）

速度相同时，随机决定先后顺序（50/50）。

### 2.4 回合状态机设计

```gdscript
enum BattlePhase {
    PHASE_INTRO,          # 战斗开始演出
    PHASE_PLAYER_INPUT,   # 等待玩家输入
    PHASE_ENEMY_THINK,    # 敌方AI选择行动
    PHASE_ORDER_RESOLVE,  # 计算行动顺序
    PHASE_EXECUTE_ACTION, # 逐一执行行动
    PHASE_END_OF_TURN,    # 回合结束处理（天气/中毒/绑定伤害）
    PHASE_CHECK_FAINT,    # 检查倒下与换人
    PHASE_BATTLE_END      # 战斗结束结算
}
```

#### 回合执行流程

```
开始新回合
    ↓
[PLAYER_INPUT] 展示行动菜单，等待玩家选择
    ↓
[ENEMY_THINK]  AI 计算并确定行动
    ↓
[ORDER_RESOLVE] 对行动列表按优先度+速度排序
    ↓
[EXECUTE_ACTION] 逐一执行（含伤害计算、动画播放、日志输出）
    ↓
[END_OF_TURN]  天气伤害 / 持续异常伤害 / 绑定倒计时
    ↓
[CHECK_FAINT]  检测是否有宝可梦 HP=0
    ├─ 有宝可梦倒下 → 触发换人流程 → 回到顶部
    └─ 双方都有宝可梦 → 回到 PLAYER_INPUT
    ↓
[BATTLE_END]   战斗胜利/失败/逃跑结算
```

### 2.5 逃跑逻辑

```gdscript
# 野生战逃跑公式（官方算法）
func calc_escape_chance(player_speed: int, enemy_speed: int, escape_attempts: int) -> bool:
    var f = (player_speed * 128 / max(enemy_speed / 4, 1)) + 30 * escape_attempts
    f = f % 256
    return randi() % 256 < f
```

- 训练家战斗**不可逃跑**
- Alpha Boss 战斗**不可逃跑**
- 每次逃跑失败，`escape_attempts` +1，下次成功率提升

### 2.6 Godot 4 实现思路

使用 `BattleStateMachine` 脚本管理所有战斗阶段：

```gdscript
# BattleStateMachine.gd
signal phase_changed(new_phase: BattlePhase)
signal action_executed(action: BattleAction, result: ActionResult)
signal battle_ended(outcome: BattleOutcome)

var current_phase: BattlePhase = BattlePhase.PHASE_INTRO
var action_queue: Array[BattleAction] = []

func transition_to(new_phase: BattlePhase) -> void:
    current_phase = new_phase
    phase_changed.emit(new_phase)
    _handle_phase(new_phase)

func _handle_phase(phase: BattlePhase) -> void:
    match phase:
        BattlePhase.PHASE_PLAYER_INPUT: _show_action_menu()
        BattlePhase.PHASE_ENEMY_THINK:  _run_ai_decision()
        BattlePhase.PHASE_ORDER_RESOLVE: _sort_action_queue()
        BattlePhase.PHASE_EXECUTE_ACTION: _execute_next_action()
        BattlePhase.PHASE_END_OF_TURN:  _process_end_of_turn()
        BattlePhase.PHASE_CHECK_FAINT:  _check_fainted_pokemon()
```

**执行行动时使用 `await` 等待动画完成**，确保不会跳帧：

```gdscript
func _execute_next_action() -> void:
    if action_queue.is_empty():
        transition_to(BattlePhase.PHASE_END_OF_TURN)
        return
    var action = action_queue.pop_front()
    await _perform_action(action)   # 等待动画+日志完成
    transition_to(BattlePhase.PHASE_EXECUTE_ACTION)  # 递归执行下一个
```

### 2.7 注意事项

- 速度相等时的随机处理必须在**每回合重新随机**，不可缓存
- 优先度相同且速度相同的多个行动之间，顺序应在排序时一次性决定，不可在执行中途更改
- 换宝可梦执行后，被换上的宝可梦**当回合不能行动**

## 3. 伤害计算系统

### 3.1 功能描述

完整实现官方宝可梦伤害公式，包括属性相克、急所判定、随机浮动、天气影响、加成叠算等核心机制。

### 3.2 官方伤害公式

```
Damage = floor( floor( floor(2 × Level / 5 + 2) × Power × A/D / 50 + 2 )
               × Modifier )

Modifier = Targets × Weather × GlaiveRush × Critical × Random × STAB
           × Type1 × Type2 × Burn × ZMove × TeraType × Others
```

#### 参数说明

| 参数 | 说明 | 数值范围 |
|------|------|----------|
| Level | 攻击方等级 | 1–100 |
| Power | 技能威力 | 通常 1–250 |
| A | 攻击方有效攻击/特攻 | 考虑等级变化和道具 |
| D | 防御方有效防御/特防 | 考虑等级变化和道具 |
| Targets | 多目标系数（单打始终为 1.0） | 0.75 / 1.0 |
| Weather | 天气加成 | 详见下表 |
| Critical | 急所系数 | 1.5（第六世代后） |
| Random | 随机浮动 | 0.85–1.00（均匀随机） |
| STAB | 属性一致加成 | 1.5（超强衔接：2.25） |
| Type1/Type2 | 属性相克 | 0 / 0.25 / 0.5 / 1 / 2 / 4 |
| Burn | 灼烧物理攻击 | 0.5（使用胡乱打/风压特性除外） |

#### 天气系数表

| 天气 | 效果 |
|------|------|
| 晴天 | 火系 ×1.5，水系 ×0.5 |
| 下雨 | 水系 ×1.5，火系 ×0.5 |
| 沙暴 | 岩石系特防 ×1.5；非岩石/钢/地面每回合 1/16 HP 伤害 |
| 冰雹 | 冰系免伤；非冰系每回合 1/16 HP 伤害 |
| 强日照/暴风雨 | 对应系 ×1.5，且对立系×0.25 |

### 3.3 属性相克表

```gdscript
# 完整 18 属性相克矩阵（攻击属性 vs 防御属性）
# 值：0=无效, 0.5=效果不佳, 1=普通, 2=很有效果

const TYPE_CHART: Dictionary = {
    # 格式: [攻击属性][防御属性] = 效果倍数
    TYPE.NORMAL: {
        TYPE.ROCK: 0.5, TYPE.GHOST: 0, TYPE.STEEL: 0.5
    },
    TYPE.FIRE: {
        TYPE.FIRE: 0.5, TYPE.WATER: 0.5, TYPE.GRASS: 2,
        TYPE.ICE: 2, TYPE.BUG: 2, TYPE.ROCK: 0.5,
        TYPE.DRAGON: 0.5, TYPE.STEEL: 2
    },
    TYPE.WATER: {
        TYPE.FIRE: 2, TYPE.WATER: 0.5, TYPE.GRASS: 0.5,
        TYPE.GROUND: 2, TYPE.ROCK: 2, TYPE.DRAGON: 0.5
    },
    # ... 完整 18×18 矩阵参考官方数据
}

func get_type_effectiveness(move_type: int, target_types: Array) -> float:
    var multiplier := 1.0
    for def_type in target_types:
        if TYPE_CHART.has(move_type) and TYPE_CHART[move_type].has(def_type):
            multiplier *= TYPE_CHART[move_type][def_type]
    return multiplier
```

#### 效果提示文本映射

| 倍率 | 战斗日志文本 |
|------|------------|
| 0 | "对 {目标} 没有效果……" |
| 0.25 | "效果不太好……" |
| 0.5 | "效果不太好……" |
| 1 | （无提示） |
| 2 | "效果拔群！" |
| 4 | "效果拔群！" |

### 3.4 急所（Critical Hit）判定

#### 急所等级与概率

| 急所等级 | 概率 |
|---------|------|
| 0（普通） | 1/24 ≈ 4.17% |
| 1（提升1级） | 1/8 = 12.5% |
| 2（提升2级） | 1/2 = 50% |
| 3（保证急所） | 100% |

急所等级提升来源：
- 高急所技能（十字刃、长眠粉等）：+1
- 聚气：+2
- 冠军眼（道具，非官方同人新增可选）：+1

急所命中时：
- 无视**攻击方**的能力下降（A/特攻下降时当做无下降处理）
- 无视**防御方**的能力上升（D/特防上升时当做无上升处理）
- 伤害 ×1.5

```gdscript
func roll_critical(crit_level: int) -> bool:
    match crit_level:
        0: return randi() % 24 == 0
        1: return randi() % 8 == 0
        2: return randi() % 2 == 0
        _: return true
```

### 3.5 随机浮动

```gdscript
func get_random_modifier() -> float:
    # 在 85 到 100 之间（含）均匀随机取一个整数，然后除以 100
    return float(randi_range(85, 100)) / 100.0
```

### 3.6 完整伤害计算函数

```gdscript
func calculate_damage(attacker: Pokemon, defender: Pokemon, move: MoveData) -> DamageResult:
    var result := DamageResult.new()

    # 选择攻防数值（物理/特殊）
    var atk: int = attacker.effective_attack if move.category == MoveCategory.PHYSICAL \
                   else attacker.effective_sp_attack
    var def: int = defender.effective_defense if move.category == MoveCategory.PHYSICAL \
                   else defender.effective_sp_defense

    # 急所处理：无视对应等级变化
    var is_critical := roll_critical(attacker.crit_level + move.crit_bonus)
    if is_critical:
        atk = max(atk, attacker.base_attack_with_items)   # 无视下降
        def = min(def, defender.base_defense_with_items)  # 无视上升

    # 基础伤害
    var base_dmg: int = int(int(2 * attacker.level / 5 + 2) * move.power * atk / def / 50 + 2)

    # 修正系数
    var weather_mod := get_weather_modifier(move.move_type, current_weather)
    var critical_mod := 1.5 if is_critical else 1.0
    var random_mod := get_random_modifier()
    var stab_mod := 1.5 if move.move_type in attacker.types else 1.0
    var type_mod := get_type_effectiveness(move.move_type, defender.types)
    var burn_mod := 0.5 if (attacker.status == Status.BURN
                            and move.category == MoveCategory.PHYSICAL
                            and not move.ignores_burn) else 1.0

    var total_mod := weather_mod * critical_mod * random_mod * stab_mod * type_mod * burn_mod
    result.damage = max(1, int(base_dmg * total_mod))
    result.is_critical = is_critical
    result.type_multiplier = type_mod

    return result
```

### 3.7 注意事项

- 伤害计算中所有 `floor` 操作顺序严格遵照官方公式，**中途不可四舍五入**
- 最终伤害最小值为 1（即使属性克制时，命中就必然造成至少 1 点伤害）
- 属性无效（倍率为 0）时跳过所有后续修正，直接输出 0 伤害
- 双属性防御方需将两个属性相克系数**相乘**，最终可达 4× 或 0.25× 等极端值

## 4. 技能系统

### 4.1 功能描述

实现宝可梦标准技能框架，支持物理/特殊/变化三类技能，以及状态异常施加、能力等级变化、持续效果等多种技能效果类型。

### 4.2 技能分类

```gdscript
enum MoveCategory {
    PHYSICAL,   # 物理：使用攻击/防御计算
    SPECIAL,    # 特殊：使用特攻/特防计算
    STATUS      # 变化：不造成直接伤害
}
```

#### 各类别典型技能举例

| 分类 | 典型技能 | 特征 |
|------|----------|------|
| 物理 | 十万马力、地震、冰冻拳 | 有威力值，接触类多 |
| 特殊 | 冲浪、雷电、火焰放射 | 有威力值，非接触 |
| 变化 | 电磁波、剑舞、解除束缚 | 威力为0，施加状态/改变能力 |

### 4.3 核心数据结构

```gdscript
class_name MoveData
extends Resource

@export var move_id: int
@export var move_name: String
@export var move_type: int              # 使用 TYPE 枚举
@export var category: MoveCategory
@export var power: int                  # 0 表示变化技能
@export var accuracy: int               # 0-100，0 表示必中
@export var pp_max: int
@export var priority: int               # -6 到 +6
@export var contact: bool               # 是否接触（影响特性和道具）
```

### 4.5 状态异常施加逻辑

#### 施加条件检查

```gdscript
func try_inflict_status(target: Pokemon, status: StatusCondition) -> bool:
    # 已有异常状态（除混乱外）不能再被施加
    if target.status != Status.NONE and status != Status.CONFUSION:
        BattleLog.print("{0} 已经有异常状态了！".format([target.name]))
        return false

    # 属性免疫检查
    match status:
        Status.PSN, Status.TOXIC:
            if TYPE.POISON in target.types or TYPE.STEEL in target.types:
                BattleLog.print("对 {0} 没有效果……".format([target.name]))
                return false
        Status.BRN:
            if TYPE.FIRE in target.types:
                return false
        Status.PAR:
            if TYPE.ELECTRIC in target.types:
                return false
        Status.FRZ:
            if TYPE.ICE in target.types:
                return false
        Status.SLP:
            if target.ability == Ability.INSOMNIA or target.ability == Ability.VITAL_SPIRIT:
                return false

    # 施加状态
    target.status = status
    if status == Status.TOXIC:
        target.toxic_counter = 1
    if status == Status.SLP:
        target.sleep_turns = randi_range(1, 3)

    BattleLog.print(_get_status_inflict_message(target, status))
    return true
```

#### 回合开始状态效果处理

```gdscript
        Status.PAR:
```

### 6.4 普通训练家 AI

```gdscript
# 策略：
# 1. 优先使用对目标属性效果拔群的技能（×2 或 ×4）
# 2. 若无克制技能，使用最高威力的技能
# 3. 变化技能概率使用（约 20%）
func trainer_easy_ai(attacker: Pokemon, target: Pokemon) -> BattleAction:
    var scored_moves: Array = []

    for move in attacker.moves:
        if move.current_pp <= 0:
            continue
        var score := 0

        if move.category != MoveCategory.STATUS:
            var effectiveness = get_type_effectiveness(move.move_type, target.types)
            score = int(move.power * effectiveness)
        else:
            score = 30 if randf() < 0.2 else 0  # 20% 概率使用变化技能

        scored_moves.append({"move": move, "score": score})

    scored_moves.sort_custom(func(a, b): return a.score > b.score)
    return BattleAction.new(attacker, ActionType.FIGHT, scored_moves[0].move)
```

### 6.6 Alpha Boss AI

Alpha Boss 使用行为树 + 脚本化阶段设计：

```gdscript
# AlphaBossAI.gd
class_name AlphaBossAI

# Boss 阶段划分
enum BossPhase {
    PHASE_1,    # HP > 66%：正常攻击模式
    PHASE_2,    # HP 33%-66%：开始使用强化技能
    PHASE_3     # HP < 33%：狂化模式，速度+攻击大幅提升，特殊技能解锁
}

var current_phase: BossPhase = BossPhase.PHASE_1
var turn_counter: int = 0

func choose_action(boss: Pokemon, target: Pokemon) -> BattleAction:
    _update_phase(boss)
    turn_counter += 1

    match current_phase:
        BossPhase.PHASE_1:
            return _phase1_logic(boss, target)
        BossPhase.PHASE_2:
            # 固定模式：每 3 回合使用一次强化技能
            if turn_counter % 3 == 0:
                return BattleAction.new(boss, ActionType.FIGHT, boss.signature_buff_move)
            return trainer_hard_ai(boss, target, null)
        BossPhase.PHASE_3:
            return _phase3_berserk_logic(boss, target)

func _update_phase(boss: Pokemon) -> void:
    var hp_pct = float(boss.current_hp) / boss.max_hp
    var new_phase: BossPhase
    if hp_pct > 0.66:
        new_phase = BossPhase.PHASE_1
    elif hp_pct > 0.33:
        new_phase = BossPhase.PHASE_2
    else:
        new_phase = BossPhase.PHASE_3

    if new_phase != current_phase:
        current_phase = new_phase
        _trigger_phase_transition_event(boss, new_phase)

func _trigger_phase_transition_event(boss: Pokemon, phase: BossPhase) -> void:
    # 播放阶段转换动画、特殊对话、音效
    BattleEventBus.emit_signal("boss_phase_changed", boss, phase)
```

#### Alpha Boss 特殊机制

| 机制 | 说明 |
|------|------|
| 愤怒计数 | 受到超过阈值伤害后，下一回合行动优先度提升 |
| 强制换技 | 进入第三阶段时解锁专属技能（如毁灭之力） |
| 复仇行动 | 被击倒至濒死时触发一次特殊行动（豁出去） |
| 逃跑阻止 | 玩家无法逃跑，且 Boss 不会换宝可梦 |

### 6.7 Godot 4 实现思路

- AI 决策通过 `AIController` 基类 + 各层子类实现多态
- `AlphaBossAI` 使用 `BehaviorTree` 插件（Beehave 或自实现）管理行为节点
- AI 决策在 `PHASE_ENEMY_THINK` 阶段同步执行，避免异步导致的顺序问题

### 6.8 注意事项

- AI 不应读取随机数后影响玩家端伪随机序列（保持随机数生成隔离）
- Alpha Boss AI 的脚本化行为（固定回合使用特定技能）须在关卡数据中配置，不硬编码在脚本中
- 高难度 AI 可预判玩家换宝（分析玩家上回合行为），但同人游戏中建议保持对玩家友好

## 7. 战斗结算系统

### 7.1 功能描述

战斗胜利后进行经验值分配、升级处理（含学习新技能）、金钱奖励及特殊道具掉落等结算流程。

### 7.2 经验值公式

#### 基础经验值计算

```
基础经验 = (基础经验值 × 敌方等级) / 7

修正经验 = 基础经验
           × 培育家修正（若培育家宝可梦 ×1.5）
           × 幸运蛋修正（若持有幸运蛋 ×1.5）
           × 亲密度修正（若亲密度≥220 且经验溢出时）
           × 对战外经验修正（大战斗设施场景可配置）
```

**经验值分组（第六世代后）**：
- 多只参战宝可梦**均分**经验值（不叠加）
- 经验分享道具（ALL EXP）开启时：全队宝可梦获得经验

```gdscript
func distribute_exp(defeated: Pokemon, participants: Array[Pokemon], shared: bool) -> void:
    var base_exp := int(defeated.base_exp * defeated.level / 7)

    for pokemon in participants:
        var exp := base_exp
        if not shared:
            exp = exp / participants.size()
        exp = apply_exp_modifiers(exp, pokemon)
        _grant_exp(pokemon, exp)

    if shared:
        # 经验分享：非参战宝可梦获得一半经验
        for pokemon in GameData.player_party:
            if pokemon not in participants and not pokemon.is_fainted():
                _grant_exp(pokemon, int(base_exp * 0.5))
```

### 7.3 升级处理

#### 升级流程

```
1. 当前经验值 >= 升级所需经验值？
    ↓ 是
2. 等级 +1，记录能力值变化（基础值 × 新等级系数）
3. 显示升级动画 + 音效
4. 显示能力值提升面板（HP/攻击/防御/特攻/特防/速度 各项变化）
5. 检查是否学习新技能（level_up_moves 表）
6. 若需学习技能：进入技能学习流程
7. 检查是否满足进化条件（等级进化）
8. 若可进化：触发进化流程
9. 继续检查是否还能再升级（连续升级）
```

#### 经验值成长类型

| 成长类型 | 等级100所需经验 | 代表宝可梦 |
|---------|----------------|-----------|
| 快速 | 800,000 | 胡地 |
| 中速偏快 | 1,000,000 | 超梦 |
| 中速偏慢 | 1,059,860 | 大部分宝可梦 |
| 慢速 | 1,250,000 | 快龙 |

```gdscript
func exp_for_level(growth_type: GrowthType, level: int) -> int:
    match growth_type:
        GrowthType.FAST:        return int(4 * pow(level, 3) / 5)
        GrowthType.MEDIUM_FAST: return pow(level, 3)
        GrowthType.MEDIUM_SLOW: return int(6/5.0 * pow(level, 3) - 15 * pow(level, 2) + 100 * level - 140)
        GrowthType.SLOW:        return int(5 * pow(level, 3) / 4)
    return 0
```

### 7.4 学习新技能流程

```gdscript

    for entry in pokemon.species.level_up_moves:

            new_moves.append(MoveDatabase.get_move(entry.move_id))
    return new_moves

func handle_new_move(pokemon: Pokemon, new_move: MoveData) -> void:
    if pokemon.moves.size() < 4:
        # 技能槽未满，直接学习
        pokemon.moves.append(new_move)
        BattleLog.print("{0} 学会了 {1}！".format([pokemon.name, new_move.move_name]))
    else:
        # 技能槽已满，进入替换选择界面
        _open_move_replacement_ui(pokemon, new_move)
```

```
  "{宝可梦名} 忘记了 {旧技能}……
```

#### 道具掉落（野生战）

```gdscript
func roll_item_drops(defeated_pokemon: Pokemon) -> Array[ItemDrop]:
    var drops: Array[ItemDrop] = []
    for entry in defeated_pokemon.species.held_item_table:
        if randf() < entry.drop_rate:
            drops.append(ItemDrop.new(entry.item_id, entry.quantity))
    return drops
```

### 7.6 战斗结算 UI 流程

```
战斗结算状态机流程：

[BATTLE_END]
    ↓
1. 播放胜利/失败/逃跑对应音效和动画
    ↓
2. 显示战斗日志最终信息
    ↓
3. 逐只宝可梦展示经验值增长动画
    （经验条缓慢填充，若升级则循环至下一级）
    ↓
4. 处理升级（能力值面板、技能学习）
    ↓
5. 显示金钱奖励（训练家战）
    ↓
6. 显示道具获取
    ↓
7. 检查进化条件 → 触发进化演出
    ↓
8. 淡出战斗场景，返回探索场景
```

### 7.7 Godot 4 实现思路

结算系统使用独立的 `BattleResultProcessor` 节点，通过 `await` 串行处理各步骤：

```gdscript
# BattleResultProcessor.gd
func process_battle_result(outcome: BattleOutcome) -> void:
    if outcome == BattleOutcome.WIN:
        await _play_victory_sequence()
        await _distribute_rewards()
        await _process_level_ups()
        await _check_evolutions()
    elif outcome == BattleOutcome.LOSE:
        await _play_defeat_sequence()
        _trigger_white_out()
    await SceneManager.return_to_overworld()
```

### 7.8 注意事项

- 连续升级（一次性升多级）须**每一级都检查**技能学习，不可跳过中间等级
- 经验值溢出（如 100 级时）应直接截止到满级上限，不循环
- 战败（全灭）时不给予经验值，并触发"白飞"流程（传送至最近的宝可梦中心）
- 进化演出应允许玩家通过按键取消（B 键），进化取消后记录宝可梦的"拒绝进化"标志，后续可手动进化
- Alpha Boss 战额外奖励（稀有道具、特殊标志）在 `process_alpha_boss_drops` 中单独处理
