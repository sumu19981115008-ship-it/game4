# ADR 001 - 初始架构搭建

**日期**：2026-05-20  
**状态**：已采纳

## 背景

基于五份策划案（核心系统、宝可梦系统、战斗系统、剧情世界、UI/UX），需要搭建整个游戏的底层架构。

## 决策

### Autoload 加载顺序

严格按以下顺序注册，确保依赖关系正确：

1. `EventBus` - 无依赖，最先加载
2. `FlagManager` - 依赖 EventBus
3. `WorldStateManager` - 依赖 EventBus、FlagManager
4. `SaveManager` - 依赖所有状态管理器
5. `PokemonDatabase` - 无依赖（只读数据）
6. `MoveDatabase` - 无依赖
7. `DialogueManager` - 依赖 EventBus、FlagManager
8. `AudioManager` - 无依赖
9. `TransitionManager` - 依赖 SceneTree
10. `SettingsManager` - 无依赖
11. `CollisionLayers` - 静态常量，无依赖
12. `NetworkManager` - 最后加载，依赖其他所有系统

### 联机预留策略

- `NetworkManager` 作为 Autoload 存在但全部方法为空实现
- 战斗行动（BattleAction）设计为可序列化的 Dictionary/Resource
- 玩家状态设计为独立的 Data 对象，方便未来接入 `MultiplayerSynchronizer`
- 伤害计算使用纯静态函数（`BattleCalculator`），方便未来迁移至服务端

### 数据与逻辑分离

- 静态数据（种族/技能/道具）存 `.tres` Resource 文件
- 动态数据（实例/存档）存 JSON
- 游戏逻辑（伤害计算/捕捉公式）存静态 class 方法

## 影响

- 未来添加联机功能时，只需填充 NetworkManager 的空方法，不需要修改其他系统
- 所有跨系统通信通过 EventBus 信号，可以随时添加新的监听者
